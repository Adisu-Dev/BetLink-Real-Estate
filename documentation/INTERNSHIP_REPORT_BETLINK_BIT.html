    EXECUTIVE SUMMARY

    This internship report details the four-month practical software engineering internship completed at Qelem Meda Technologies PLC (QMT), an ISO/IEC 27001:2022 (Information Security) and ISO 9001:2015 (Quality Management) certified enterprise software company based in Addis Ababa, Ethiopia. The primary goal of the internship was to translate theoretical software engineering knowledge into professional software engineering competencies, contribute actively to enterprise-grade software products, and address real-world socio-economic problems through digital automation.

    Assigned to the System Development Department (Web Application and Backend Engineering Unit), I participated actively across all phases of the Software Development Life Cycle (SDLC) following Agile Scrum principles. My technical assignment culminated in the design, architectural engineering, implementation, and deployment of BetLink, a modern, multi-tier real estate marketplace and automated property management system tailored to the Ethiopian socio-economic ecosystem.

    The real estate sector in Ethiopia has historically been constrained by informal, unverified brokers ("delalas"), high information asymmetry, lack of localized and standardized digital records, payment insecurities, and inadequate multi-lingual access for diverse regional populations. BetLink was engineered to resolve these challenges by providing:

    1. A secure, role-based multi-portal platform serving Buyers/Tenants, Property Owners/Landlords, Certified Real Estate Agents, and Platform Administrators.

    2. A high-throughput RESTful API architecture built on Laravel 11, leveraging Sanctum token authentication, multi-channel OTP verification (Email and SMS), and granular middleware authorization.

    3. A responsive, dynamic Single Page Application (SPA) frontend built on Vue.js 3 (Composition API) and Vite, featuring interactive property discovery, instant geospatial filtering, dual-theme dark/light glassmorphic UI, and multi-lingual localization (Amharic, Afaan Oromoo, Tigrinya, and English).

    4. Performance optimization using in-memory request deduplication and Stale-While-Revalidate (SWR) caching (cachedGet), reducing client response times to under 100 milliseconds.

    The report covers five detailed parts: Part One introduces administrative and preliminary documentation; Part Two provides an in-depth organizational analysis of Qelem Meda Technologies PLC; Part Three documents the internship experience, technical tasks, engineering methodologies, challenges faced, and multi-dimensional skill enhancements; Part Four presents the comprehensive engineering specification, design diagrams, database schema, implementation details, and testing outcomes of the BetLink system; and Part Five delivers holistic conclusions and strategic engineering recommendations for academia and industry.

    • 3.4 Major Technical and Operational Challenges Identified

    During my immersion in the project workflow, I encountered and diagnosed several critical software engineering and operational challenges:

    1. Database Connection Latency and Cascading Service Failures: Under local test setups, when MySQL database services terminated unexpectedly, Laravel's PDO connection driver attempted repeated retries, blocking HTTP execution for 8 to 15 seconds before returning 500 error responses. This resulted in client interfaces freezing in perpetual skeleton-loader states without informative fallback alerts.

    2. Over-Cluttered Frontend Forms and Poor User Psychology: Early versions of the user registration portal displayed intrusive password checklists, rigid strength meters, and redundant social buttons, creating cognitive overload and discouraging user completion.

    3. Multi-Lingual Hardcoding and Inconsistent Localized Strings: Components frequently contained hardcoded English labels juxtaposed with translated Amharic strings (e.g., displaying © 2026 BetLink Real Estate alongside ደህንነቱ የተጠበቀ ምስጠራ), disrupting visual harmony and confusing regional users.

    4. High Network Latency on Repeated Feed Filtration: Every minor filter adjustment (e.g., toggling bedrooms or property types) initiated a blocking HTTP roundtrip, straining server resources and creating perceived sluggishness over slower mobile internet connections.

    3.5 Remedial Measures, Solutions, and Workarounds Implemented

    To resolve these challenges, I engineered systematic technical solutions:

    1. SWR Caching and Defensive Error Handling: Introduced an in-memory client cache (cachedGet) with in-flight promise deduplication in api.js. If multiple identical requests are triggered concurrently, they share a single network promise. Successful responses are cached for 30–60 seconds, allowing subsequent filter switches to resolve in 0ms. Furthermore, UI components were enhanced with explicit, user-friendly error boundaries and retry triggers.

    2. Form Streamlining and Internalized Password Validation: Removed distracting visual password meters from the registration form while retaining rigorous internal validation algorithms on the frontend and backend. Password complexity is evaluated transparently, preserving a clean, distraction-free user interface.

    3. Comprehensive Localization Normalization: Audited and normalized locale files (en.js, am.js, om.js, ti.js), migrating hardcoded visual panel labels and copyright notices into localized translation keys with dynamic year interpolation ({year}), ensuring consistent linguistic presentation across all viewports.

    4. Database Daemon Resilience: Configured MariaDB startup parameters, verified connection pooling, and optimized Eloquent queries using eager loading (with(['propertyType', 'address.city', 'primaryImage'])), mitigating the notorious $N+1$ query problem and accelerating query execution.

    PART FOUR: PROJECT WORK – BETLINK REAL ESTATE PLATFORM

    4.1 Summary of the Project

    BetLink is a modern, enterprise-grade, full-stack real estate marketplace and automated property management platform engineered specifically for the Ethiopian urban context. Built using a decoupled three-tier architecture comprising a Laravel 11 RESTful backend and a Vue.js 3 Single Page Application (SPA), BetLink centralizes and digitalizes the fragmented real estate ecosystem. It provides dedicated, role-tailored portals for Buyers/Tenants, Property Owners/Landlords, Licensed Real Estate Agents, and Platform Administrators. The system integrates localized property discovery, multi-channel OTP verification (email and SMS), virtual appointment scheduling, direct inquiry messaging, verified badge governance, and full quad-language localization (Amharic, Afaan Oromoo, Tigrinya, and English).

    4.2 Problem Statement and Justification

    4.2.1 Problem Statement

    The real estate market in major Ethiopian metropolitan areas—most notably Addis Ababa, Hawassa, Adama, and Bahir Dar—is plagued by structural inefficiencies:

    1. Informal and Unvetted Broker Networks ("Delalas"): Real estate transactions rely predominantly on informal street brokers who operate without professional licenses, accountability, or price consistency, routinely inflating rental and purchase prices by 15% to 30%.

    2. Severe Information Asymmetry and Fraud: Prospective home buyers and tenants encounter misleading descriptions, fake ownership claims, duplicate property listings, and illegal subleases, resulting in legal disputes and financial losses.

    3. Lack of Centralized, Standardized Platforms: Existing listing mechanisms are fragmented across unorganized Telegram channels, social media groups, and word-of-mouth networks lacking search filters, standardized specifications, or verified ownership badges.

    4. Linguistic and Regional Exclusion: The vast majority of existing digital listing experiments are available exclusively in English, effectively alienating millions of property owners, tenants, and rural-urban migrants fluent in Ethiopia's primary national languages (Amharic, Afaan Oromoo, and Tigrinya).

    5. Inefficient Manual Property Management: Landlords and property managers track tenant leases, maintenance requests, and rental income using manual paper records, causing rent collection delays and unorganized accounting.

    4.2.2 Justification

    Developing BetLink directly addresses these national challenges by creating a transparent, verified, and localized digital real estate ecosystem. By incorporating multi-channel OTP verification, document-backed ownership verification, and transparent direct communication between clients and verified owners/agents, BetLink eliminates predatory brokerage fees. Furthermore, its quad-language reactive engine ensures that software technology is democratized and accessible across regional borders, aligning directly with Ethiopia's Digital Ethiopia 2025 national transformation agenda.

    • 4.7.2 High-Speed Property Search and SWR Caching

    To ensure instant responsiveness, api.js implements a custom Stale-While-Revalidate (SWR) caching mechanism with in-flight request deduplication:

    // Enhanced Cached GET with In-Flight Deduplication and SWR
export async function cachedGet(url, config = {}) {
  const cacheKey = GET:${url}:${JSON.stringify(config.params || {})}
  const now = Date.now()
  const ttl = config.ttl !== undefined ? config.ttl : DEFAULT_CACHE_TTL

  // 1. Return fresh cached entry immediately (0ms)
  if (responseCache.has(cacheKey)) {
    const entry = responseCache.get(cacheKey)
    if (now - entry.timestamp < ttl) {
      return entry.data
    }
  }

  // 2. Deduplicate in-flight requests
  if (inFlightRequests.has(cacheKey)) {
    return inFlightRequests.get(cacheKey)
  }

  // 3. Dispatch network request and cache result
  const requestPromise = apiClient.get(url, config).then((data) => {
    responseCache.set(cacheKey, { timestamp: Date.now(), data })
    inFlightRequests.delete(cacheKey)
    return data
  }).catch((err) => {
    inFlightRequests.delete(cacheKey)
    throw err
  })

  inFlightRequests.set(cacheKey, requestPromise)
  return requestPromise
}
